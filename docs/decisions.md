# 技术决策

## 2026-07-16：第一版技术选型

- 前端：Vue 3 + TypeScript + Vite
  - 原因：复用已有前端经验，把主要学习重点放在 Go 后端。

- 后端：Go + 标准库 net/http
  - 原因：先理解 HTTP、路由、JSON 和错误处理的基础，再评估是否需要 Gin。

- 数据库：SQLite
  - 原因：本地单文件数据库，适合个人知识库；后期部署仍可继续使用。

- 用户系统：第一版不做登录
  - 原因：先跑通前端、后端和数据库的完整流程，避免权限设计扩大范围。


## 2026-07-16：产品定位与可扩展性

项目定位为“个人优先、可演进为多人协作的知识库”。

第一版只服务本地单用户，不提供登录、注册、公开访问或文件上传。
但数据模型从一开始保留工作空间和笔记可见性的边界：

- 分类和笔记属于工作空间。
- 笔记默认私有，后期可设置为公开。
- 后期用户通过成员关系加入工作空间。
- 附件上传必须在认证、权限校验和存储策略完成后才开放。

演进顺序：个人知识库 -> 公开阅读知识库 -> 用户与工作空间 -> 附件和协作。

## 2026-07-16：仓库与 Go Module 路径

- GitHub 仓库：`https://github.com/XiaoMoDern/dev-knowledge-base.git`
- 后端 Module：`github.com/XiaoMoDern/dev-knowledge-base/backend`

原因：Go Module 路径与未来远程仓库路径保持一致，后续内部包和第三方使用者能通过稳定路径识别该模块。

## 2026-07-16：本地开发端口

- Go 后端开发地址：`http://127.0.0.1:8181`
- Vue 开发地址：`http://127.0.0.1:5173`

原因：本机的 8080 已被其他项目使用。前端后续通过 Vite 代理将 `/api` 请求转发到 8181，因此页面代码不需要写死后端端口。部署时端口由运行环境配置，不受本地端口选择限制。

## 2026-07-16：知识内容的源文件格式

`docs/knowledge/` 作为知识条目的 Markdown 源目录，与项目过程文档分离。每条知识内容使用 YAML front matter 保存 `id`、标题、分类、标签和摘要，正文使用 Markdown。

原因：当前可直接在 Git 中审阅和积累笔记；后续可由 Go 程序解析这些文件，导入 SQLite，避免手工重复录入已有学习内容。
